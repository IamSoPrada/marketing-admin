# UX-flows

Актуальная карта сценариев реализованного прототипа. Наследует `PROJECT_FLOWS.md` первой версии с правками из UX-ревью.

## Навигация

- Sidebar: Обзор, Подборки (со счётчиком), Сотрудники, Роли, Настройки; переключатель рабочего пространства (popover: переключение + создание); Помощь (модалка FAQ + поддержка). На < lg — компактный режим с иконками.
- Header: breadcrumbs, popover уведомлений (список + «Прочитать всё»), меню профиля (настройки профиля и 2FA → `/profile`, выход → `/sign-in`).

## Подборки

### Список
- Вкладки **Активные / Архив** со счётчиками — архив стал адресуемым местом (в первой версии подборка архивировалась «в никуда»).
- Поиск по названию **и slug** (как обещает placeholder), фильтры статуса/типа, empty states (нет результатов / пустой архив / пустой список), клиентская пагинация.
- Клик по названию → редактор. Кнопка `...` → контекстное dropdown-меню вместо универсальной модалки.

### Действия строки
| Действие | Реализация |
|---|---|
| Открыть предпросмотр | Модалка «глазами покупателя» + переход в редактор |
| Редактировать | Мастер в edit-режиме с предзаполнением |
| Дублировать | Модалка: название копии + что копировать; результат — новый черновик |
| Опубликовать | ConfirmDialog **с чек-листом проверок** (состав ≥ 8, название, описание, SEO) |
| Снять с публикации | ConfirmDialog с последствиями |
| Архивировать | ConfirmDialog → вкладка «Архив», откуда доступно «Восстановить» |
| Удалить | Destructive ConfirmDialog с именем объекта и предупреждением о необратимости |

### Мастер (создание `/collections/new`, редактирование `/collections/:id/edit`)
- Степпер 4 шага: **Состав → Предпросмотр → Оформление → Публикация**. Вперёд — только после валидного шага; назад и по уже пройденным шагам — свободно. В edit-режиме все шаги доступны сразу.
- Шаг 1: тип подборки (ручная/живая), фильтр по игре, живой поиск по каталогу, **живой счётчик** «N из 8 минимум», двухпанельный список (каталог ↔ выбранные), порядок стрелками, удаление.
- Шаг 2: переключатель desktop/mobile preview.
- Шаг 3: название (обязательно), slug с автогенерацией из названия (транслитерация), inline-проверки формата и уникальности, описание, основной цвет.
- Шаг 4: SEO-поля со счётчиками длины, **чек-лист публикации, вычисляемый из реальных данных**, со ссылками «Перейти к шагу»; «Опубликовать» активна только при пройденных проверках.
- «Сохранить черновик» — реальное сохранение в стор + тост + возврат к списку.
- Защита от потери данных: `onBeforeRouteLeave` + ConfirmDialog при несохранённых изменениях.

## Сотрудники

- Рабочий поиск (имя/почта), фильтр статуса (включая «Отключена» — в первой версии отсутствовал).
- Приглашение: валидация email, ошибка дубликата, выбор роли, success-тост. Открывается также из дашборда (`/employees?invite=1`).
- Действия: изменить роль (модалка), повторная отправка приглашения (только для pending), сброс 2FA (confirm), отключить/включить учётную запись (confirm с разными текстами), отозвать доступ (destructive confirm).

## Роли

- Карточки ролей: права, число сотрудников, меню `...`.
- Редактор: название, описание, **матрица прав по группам** с групповым чекбоксом (все/частично/нет).
- Системную роль нельзя удалить и переименовать (пункт меню disabled с объяснением).
- Удаление — destructive confirm; если у роли есть сотрудники, текст предупреждает о последствиях.

## Настройки

- Форма пространства (название, описание, цвет, доступ) с сохранением в стор и тостом.
- Переключатели уведомлений (локальные mock-предпочтения).
- «Опасная зона» с заблокированным удалением пространства (до backend).

## Профиль

- `/profile`: личные данные (аватар с инициалами, имя, рабочая почта) с сохранением и тостом.
- Безопасность: смена пароля (текущий + новый + подтверждение, новый ≥ 8 символов, кнопка неактивна при несовпадении), переключатель 2FA.
- Из меню профиля в шапке сюда ведут «Настройки профиля» и «Настройка 2FA»; «Настройки» в сайдбаре остаются настройками пространства.

## Auth

- `/sign-in`: валидация пустых полей, «Запомнить меня», ссылка на сброс.
- `/two-factor`: 6-значный код, переключение на резервный код, повторная отправка с таймером 30 с, лимит 5 попыток с блокировкой, после успеха — переход в `/overview` (в первой версии был тупик «Код принят»).
- `/sign-up`: код приглашения с состояниями истёк/использован, имя, требования к паролю с живым чек-листом, совпадение паролей; после успеха — экран «подключить 2FA».
- `/forgot-password`: отправка ссылки + нейтральный success-текст (не раскрывает существование аккаунта).

## Общие принципы (Definition of Done)

- Любое действие → предсказуемый результат: навигация, dropdown, modal, toast или mutation стора.
- Деструктивное действие → отдельный ConfirmDialog с именем объекта.
- Формы сохраняют введённые значения при ошибках; ошибки — рядом с полем.
- Долгие операции → spinner в кнопке, повторный submit заблокирован.
- После успеха → тост + обновление списка/счётчиков.
- Touch-targets ≥ 40px, focus-visible, aria-атрибуты на иконочных кнопках и полях с ошибками.
