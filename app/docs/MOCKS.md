# Мок-слой

## Принцип

Все данные живут в Pinia-сторах в памяти вкладки. Каждая операция — async-функция с имитацией задержки (`mockDelay`, ~350 мс), чтобы в UI были видны loading-состояния. При подключении backend меняется только реализация методов стора — компоненты не трогаем.

## Осознанные mock-ограничения

- **Нет персистентности.** Перезагрузка страницы сбрасывает всё к исходному набору.
- **Авторизация имитирована.** `/sign-in` принимает любые непустые данные; на `/two-factor` код `000000` — неверный (для демо ошибок и лимита попыток), любой другой 6-значный — верный.
- **Приглашения.** На `/sign-up` коды `MK-OLD` / `MK-EXPIRED` показывают «истёкшее», `MK-USED` — «уже использовано». Письма, естественно, не отправляются.
- **Slug-проверки** выполняются против локального списка (гонки двух вкладок невозможны в mock).
- **Права ролей** описаны в данных (permissions matrix), но не ограничивают UI — ролевой доступ появится с реальной авторизацией.
- **Профиль** (`/profile`) — локальный `ref` внутри страницы, без стора: сохранение только имитирует задержку и показывает тост, данные никуда не пишутся. При подключении backend завести стор пользователя в `common/shared/state/` и привязать к нему форму профиля и шапку (сейчас имя/почта в `AppHeader.vue` захардкожены).

## Как заменить на реальный API

1. Добавить HTTP-клиент в `src/common/shared/api/httpLayer.ts` (fetch/ofetch с базовым URL, обработкой 401/403, ретраями).
2. В каждом сторе заменить тело методов на вызовы httpLayer, оставив сигнатуры: например, `invite(email, roleId): Promise<string | null>` — ошибка строкой для inline-показа, `null` при успехе.
3. Исходные данные сторов инициализировать из API на входе в приложение (app plugin или server route).
4. `mockDelay` и `nextId` удалить вместе с `api/mock.ts`.
